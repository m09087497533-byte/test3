# AI Footage Editor — читаемый текст на сетке, v4

Запуск остаётся `python3 main.py`. Нет обращений к FastGen или облачным
сервисам ИИ. Поиск видео по-прежнему использует Pexels/Pixabay.
Подробная инструкция: [START_HERE.txt](START_HERE.txt).

## Текст на сетке теперь можно прочитать

Вариант **«Бегущие строки на сетке»** автоматически раскладывает фразу
в 2–4 сбалансированные строки, сохраняя целые слова. Фраза сразу видна
целиком и медленно смещается всего на 2,4% ширины кадра за всё появление.
Сетка остаётся неподвижной. Одно слово не делится на искусственные строки.

Когда позволяет место до следующего акцента и конца озвучки, текст остаётся
на 4–8 секунд в зависимости от длины. Начало появления, озвучка и смены
футажей не сдвигаются. Продолжение текста через склейку не запускает новый
звук. Изменение действует и в старых проектах с выбранным вариантом сетки;
выбирать его заново не требуется.

[Демонстрация](https://github.com/m09087497533-byte/test3/raw/refs/heads/main/downloads/ai-footage-editor-readable-grid-v4-demo.mp4)
и [кадр готового видео](docs/readable-grid-v4.png).

## Как изменить появление

1. Нажми **«План акцентов»** и выбери строку.
2. Справа открой список **«Появление выбранного акцента»**. Доступны
   **26 вариантов и автоматический выбор**: проявление, печатная машинка,
   выезды с четырёх сторон, приближение, уменьшение, пружина, подскок,
   фокус, перспектива, раскрытия, штамп, поворот, вертикальное раскрытие,
   подпись, карточка, подчёркивание, обводка, красный акцент, неон,
   цветная тень и строка на сетке.
3. Выбор сразу сохраняется в проекте и применяется в экспортируемом видео.
   Предпросмотр показывает анимацию по кругу; его можно поставить на паузу.
   «Применить ко всем акцентам» меняет текущий план целиком.
   «Вернуть всем автоматический выбор» возвращает исходные появления.

Текст, начало появления и частота акцентов при смене варианта не меняются.
Для текста на сетке время чтения увеличивается в пределах свободного места.
Смена футажа не сбрасывает выбор. Полная выбранная фраза видна под таблицей,
у таблицы есть прокрутка. [Окно настройки](docs/appearance-editor.png).

Все пять основных кнопок — аудио, транскрибация, импорт субтитров, подбор
и сборка видео — теперь расположены **в одной строке**. «Стоп» появляется
в строке статуса, сохраняя расположение основных кнопок.

[Демонстрация восьми появлений](https://github.com/m09087497533-byte/test3/raw/refs/heads/main/downloads/ai-footage-editor-appearances-v3-demo.mp4):
восемь коротких реальных экспортов с разными сохранёнными вариантами,
собранных в один технический обзор. Иллюстрации собственные; озвучки нет.
Кадры в начале и после появления: [галерея вариантов](docs/appearances-v3-frames.jpg).

## Переходы и автоматический монтаж

К прежним 11 эффектам добавлены тёплая засветка, сине-розовый перелив,
зум-переход, плавный сдвиг, размытие, шторка и световая вспышка.
Отмеченные чекбоксами эффекты раздаются **по кругу в порядке списка**, как раньше:
например, панорама → засветка → перелив → панорама → засветка → перелив.
«Без эффекта» тоже занимает место в цикле. Первая сцена не имеет входящего
перехода. Новые переходы применяются на границе перед назначенной сценой,
аналогично прежнему растворению. Длины сцен и очередь подбора не меняются.

Автоматические акценты накладываются поверх уже собранного видеоряда:
красные даты с рисующейся обводкой, светящиеся цифры, даты с цветной тенью,
жёлтая строка на неподвижной сетке, перспективные появления и короткие подписи.
Текст берётся из распознанной речи или импортированных субтитров. Даты,
числа и знакомые выражения обрабатываются правилами; для других тем
используются короткие законченные фразы. Это не генеративный анализ смысла.
Положение слова внутри исходной реплики оценивается по длине слов.

По умолчанию включены текст и максимум два крупных акцента в минуту;
короткие подписи имеют отдельный предел — три в минуту. Частоту крупных
можно менять от 0 до 4. «План акцентов» показывает время, текст и превью.
Продолжение акцента через смену футажа не запускает его заново.
Звуки выключены по умолчанию. Если включить «Звуки акцентов», короткие
локально созданные звуки звучат только при появлении текста, максимум
четыре в минуту. На переходах звуков нет.

Настройки сохраняются в проекте. Старые проекты открываются с прежними
клипами, кандидатами, своими запросами и выбранными эффектами. Поиск,
переподбор, ручное назначение, импорт SRT/VTT и локальные модели сохранены.
Двенадцать исходных файлов поиска/запуска и девять обработчиков окна
сверены с загрузкой пользователя: [PRESERVED_SOURCE.json](PRESERVED_SOURCE.json).

Для обновления закрой программу, сохрани резервную копию её папки и замени
файлы программы **вместе со всей папкой `accents` и шрифтами**. Существующий
`.env`, `.venv-local` и папки `<имя_аудио>_project` сохрани. Новых зависимостей
для этих эффектов нет. Если окружение уже работало, запускай как прежде.

Демонстрация: [MP4](https://github.com/m09087497533-byte/test3/raw/refs/heads/main/downloads/ai-footage-editor-transitions-v2-demo.mp4).
Это технический ролик на собственных иллюстрациях и тишине: восемь сцен,
два полных цикла `none → light_leak → color_wash → transition_zoom`,
четыре крупных акцента в минуту и включённые звуки для проверки.
Это не пример качества поиска и не озвучка пользователя.

## Однократная подготовка на Mac

В Терминале:

```bash
brew install python@3.12 python-tk@3.12 ffmpeg
```

Затем в папке с `main.py`:

```bash
python3 setup_local.py
python3 main.py
```

В дальнейшем нужна только последняя команда. `bootstrap.py` до импорта
Tkinter переключает процесс на `.venv-local/bin/python`. Поэтому команда
может изначально вызываться установленным Python 3.14 без Tkinter, а окно
откроется подготовленным Python 3.12. Установщик не меняет системный Python,
не пишет алиасы и не требует `--break-system-packages`. Он проверяет импорт
Tkinter выбранного интерпретатора до установки библиотек. Python 3.11 также
поддерживается, если уже установлен с Tkinter.

Старое `.venv` от предыдущего Install.command не используется. `.env` с
существующими ключами не перезаписывается. В новом шаблоне нужны только
`PEXELS_API_KEY` и/или `PIXABAY_API_KEY`. Старые параметры FastGen игнорируются.

## Анализ на компьютере

- **Речь:** `faster-whisper`, CPU/int8, модель `base` по умолчанию.
- **Перевод RU→EN:** `Helsinki-NLP/opus-mt-ru-en` через Marian.
- **Кадры:** `openai/clip-vit-base-patch32`, локальный PyTorch CPU.
  Это открытые веса модели, а не обращение к OpenAI API.
- **Видео:** FFmpeg/ffprobe, исправленная шкала пауз и переходов.

Модели лениво скачиваются с Hugging Face в `~/.cache/ai_footage_models` при
первом использовании. Можно задать `LOCAL_MODELS_DIR`. При наличии локального
кеша сначала загружаются веса без сетевого обращения. На зависимости и модели
нужно несколько гигабайт диска; скорость зависит от ноутбука. Аудио/кадры
не отправляются на сервер для анализа. Запросы поиска уходят стоковым сервисам.

Импорт SRT/VTT работает без запуска распознавания речи. Модель Whisper
создаётся на время транскрибации и освобождается после неё.

## Подбор

1. По всему рассказу извлекаются частые ключевые слова темы. Это ключевые слова,
   а не сгенерированное резюме. Они переводятся локально.
2. Текущий сегмент и две предыдущие/одна следующая сцены переводятся локально.
3. Из содержательных слов строятся несколько коротких английских запросов.
   Это эвристика, не генеративная модель сценария. Неудачный запрос можно
   заменить в поле под текстом сцены; своё значение сохраняется при поиске.
4. Найденные клипы обоих сайтов объединяются по ID. Предварительная очередь
   определяется реальными тегами/заголовками, а не поисковым запросом.
5. Превью сравниваются с текстом через CLIP. Для лучших кандидатов извлекаются
   три кадра из используемого отрезка от начала клипа и оцениваются отдельно.
6. Текстовый вектор: текущая сцена 80%, предыдущие 12%, следующая 3%, тема 5%.
   Пустые части исключаются с перенормировкой весов. CLIP имеет ограниченную
   длину текста; длинные сцены лучше разбивать по исходным таймкодам.
7. Итог кадров: 70% среднего сходства + 30% наименьшего сходства.
   Это уменьшает влияние одного удачного кадра среди неподходящих.
8. Автовыбор допускает только клипы с тремя сравнёнными кадрами и сходством
   выше порога. При отсутствии подходящих расширяется поиск. Повторы
   учитываются среди близких оценок. При ошибке загрузки пробуется следующий
   допущенный кандидат. «Ещё варианты» переходит на следующую страницу.

Отображаемый балл — косинусное сходство × 100, не вероятность правильности.
Порог 0.22 — начальная эвристика, не откалиброванная на ваших рассказах.
CLIP не умеет надёжно подтверждать действие, отрицание, историческую эпоху
или личность конкретного человека. Система не заявляет «точное соответствие»
по одному такому баллу. Проверяйте спорные сцены вручную.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `WHISPER_MODEL` | `base` | Локальная модель речи; `small` тяжелее |
| `WHISPER_LANGUAGE` | `ru` | Язык; пустое значение — автоопределение |
| `SEARCH_PER_PROVIDER` | `6` | Результаты каждого сайта на запрос |
| `LOCAL_PREVIEW_LIMIT` | `12` | Максимум превью на этап |
| `LOCAL_FRAME_LIMIT` | `4` | Максимум клипов с тремя кадрами на этап |
| `LOCAL_MIN_SIMILARITY` | `0.22` | Минимальное сходство для автовыбора |

Резервный поиск может добавить ещё один этап. Повышение лимитов замедляет
подбор, но увеличивает число проверяемых клипов. Кеш включает переводы,
эмбеддинги, картинки, контекст и версию алгоритма. Ошибки не кешируются;
выдача поиска хранится 24 часа. Временные видео для анализа удаляются.

## Совместимость и монтаж

Старые `project.json` читаются; назначенные клипы сохраняются. Для пересмотра
используйте «Переподобрать сток». Новые ручные назначения и локальные файлы
защищены от автозамены; в старом формате ручные назначения стока не отличались
от автоматических. Без успешной замены старый клип остаётся с отметкой проверки.

Паузы учитываются ровно один раз. Растворения компенсируются на каждом стыке,
а не замороженным кадром в конце. Границы привязаны к сетке 25 fps. Поддержаны
реальные обычные склейки в ролике с растворениями и сборка переходов блоками.
При повреждённом назначенном клипе выводится ошибка. Сцены без клипов дают
чёрный экран только после прежнего предупреждения интерфейса.
