# Кадр — видеомастерская

## v17: озвучка → текст → монтаж

Загрузите только голос: `faster-whisper` распознает речь на CPU, режиссёр построит
сцены по таймкодам, затем начнётся обычный подбор фото и видео. Доступны языки,
автоопределение, модели tiny/base/small/medium, ручной запуск и остановка.
При первой загрузке модели нужен интернет: примерно 75 МБ / 145 МБ / 480 МБ /
1,5 ГБ соответственно. Модель хранится в `.data/models/whisper`. Время работы
и качество зависят от компьютера, языка и записи; имена и термины проверяйте.
Аудио обрабатывается на компьютере с сервером Кадра, в облачное API распознавания
не отправляется. Обновление страницы продолжает проверку задания; новый проект,
загрузка SRT/VTT и удаление голоса останавливают распознавание. После перезапуска
сервера незавершённое распознавание нужно запустить заново.

Локальная многоязычная модель MiniLM через `fastembed` сравнивает смысл речи
и **описаний** найденных материалов на разных языках. В новом проекте она
включена и скачивается при первом подборе (около 220 МБ); можно подготовить
её заранее кнопкой в панели подбора. Скачанная модель загружается после перезапуска
без сети. Старые проекты сохраняют прежний режим; включите смысловую оценку
для них отдельно. При недоступной модели остаётся подбор по словам с явным
сообщением в панели. Смысловая оценка не обходит проверки страны и главного
предмета, не распознаёт изображение, не генерирует картинки и не гарантирует
подходящих кадров для любой темы. Обычный поиск по словам и прежние тематические
правила сохранены; качество общей модели здесь пока не измерено.

В блоке «Текст и таймкоды» есть **«Исправить фразы»** и **«Скачать SRT»**.
Исправления обновляют акценты, сохраняя таймкоды, голос, музыку и назначенные
материалы. Для обновления картинок после правки запустите подбор с заменой;
просмотр и экспорт потребуют пересборки. Фразы нельзя оставлять пустыми.

«Запустить Кадр.command» и «Обновить Кадр.command» ставят `requirements-ai.txt`.
Если установка дополнительных библиотек не удалась, основное приложение
продолжает запускаться с SRT/VTT. Для ручной установки:

```bash
.venv/bin/python -m pip install -r requirements-ai.txt
```

Моделям нужен доступ к `huggingface.co` и CDN Hugging Face/Xet. Пакеты и модели
не включены в архив. При сетевом запрете не отключайте проверку TLS; разрешите
нужные домены в настройках сети. Pexels/Pixabay по-прежнему требуют собственных
ключей; Wikimedia может ограничивать запросы. Пустой проект больше не запускает
поиск материалов сам по себе.

## Новая установка на Mac

Распакуйте полный архив `kadr-studio-v17.zip` в новую папку и откройте двойным
щелчком **`Запустить Кадр.command`**. При первом запуске программа создаст в этой
папке `.venv` и установит библиотеки; нужен интернет. Если macOS блокирует файл,
выберите «Открыть» через контекстное меню. Оставьте окно Терминала открытым во
время работы. При следующих запусках открывайте этот же файл. Скрипт
«Обновить Кадр.command» для новой установки не нужен.

Нужны Python 3.10+ и FFmpeg. При установленном Homebrew стартовый файл сам
установит отсутствующий FFmpeg. Если Homebrew отсутствует, установите его по
инструкции на brew.sh, затем повторите запуск. Для нового рассказа нажмите
**«＋ Новый проект»** и загрузите озвучку. Распознавание запустится автоматически; SRT/VTT можно загрузить вместо него.

Архив не содержит пользовательскую `.data`. Если распаковать его **рядом со
старой папкой Кадра**, стартовый файл скопирует из неё исходные материалы и
ключи стоковых сервисов. Браузер восстановит предыдущий проект, когда все
его исходники доступны. Если папки расположены отдельно, перенос не произойдёт.
Старую папку удаляйте только после проверки проекта и скачанного MP4.

Если прежний монтаж не найден, новый проект показывает пустую сцену; после загрузки голоса и SRT/VTT создаёт сцены
по новому рассказу и запускает подбор для всех сцен. В смешанном режиме
программа сравнивает фото Wikimedia/Pexels/Pixabay и футажи Pexels/Pixabay.
Один найденный материал используется максимум в двух несоседних сценах.
Крупных текстовых вставок вместе с вынужденными заменами — до двух в минуту.
Вертикальные фото документов в рамке получают плавный автоматический наезд;
направление появления и движения меняется между сценами. При сборке каждая
сцена и каждый переход проверяются по числу кадров. На FFmpeg 9 при сбое
склейки программа повторяет её без опоры на временные метки MP4.
Если источник ограничил загрузки, незаполненные сцены остаются в отчёте и
экспорт просит повторить подбор; текст не размножается на весь фильм.
Для выбранной сцены доступны замена
кадра, поиск другого варианта, правка текста и повторная сборка сцены. Новый
проект автоматически добавляет тихую оригинальную мелодию, если загружен голос
и не выбрана своя музыка. Аудиоэффекты назначаются редко и автоматически.

Первая рабочая версия генератора документальных видеороликов. Исходные данные — **твоя озвучка и субтитры SRT или VTT**. Приложение создаёт монтажную основу по таймкодам, позволяет оформить сцены и экспортирует настоящий MP4.

После загрузки субтитров программа может сама подобрать и назначить фото и видео к сценам. Для текущего монтажа есть кнопка «Подобрать и расставить». Используются библиотека, Wikimedia Commons и подключённые Pexels/Pixabay. Подбор основан на теме и ключевых словах; перед экспортом просмотрите результат. Генерация новых иллюстраций пока не встроена.

## Как запустить

Открытие `static/index.html` или его предпросмотра внутри чата **не запускает приложение**: обработка видео требует Python-сервера и FFmpeg. Страница загружается через сервер, а не двойным щелчком по HTML.

Нужны Python 3.10+ и FFmpeg с H.264 (libx264), AAC и стандартными видеофильтрами. Фильтр `ass` (libass) необязателен: без него субтитры отрисовываются Pillow. Кириллические шрифты DejaVu включены в проект вместе с лицензией.

На macOS системные инструменты можно установить через Homebrew:

```bash
brew install python ffmpeg
```

На Debian/Ubuntu:

```bash
sudo apt-get install python3-venv ffmpeg
```

Затем **из папки проекта**:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 run.py
```

Браузер откроется автоматически после готовности сервера. Остановить сервер — Ctrl+C. Для серверной среды: `python3 run.py --no-browser`. Порт меняется через `--port 8001`.

В подготовленной облачной среде:

```bash
cd /workspace/test1
.venv/bin/python run.py --no-browser
```

Приложение слушает только loopback. Публичное размещение и доступ из интерфейса чата не настроены; эта сборка рассчитана на локальное использование одним пользователем. Облачный сервер сам по себе не создаёт ссылку предпросмотра.

## Первый ролик

1. Загрузи озвучку (MP3, WAV, M4A, OGG, FLAC).
2. Добавь SRT или VTT. Приложение заменит текущий монтаж сценами по таймкодам, сохранив материалы и озвучку.
3. Автоподбор начнётся после импорта субтитров, если включён переключатель «Запускать после загрузки субтитров». Для существующих сцен нажмите «Подобрать и расставить». Фото и видео будут назначаться автоматически; прогресс показан по сценам.
4. Выбери оформление: «Кино», «Архив», «Акцент», «Цитата» или «Тезис». При необходимости добавь заголовок, подпись и музыку.
5. Нажми «Экспорт MP4», дождись результата и скачай его. Встроенный плеер показывает именно готовый файл.

**SRT**: UTF-8 или Windows-1251, стандартные таймкоды `00:00:00,000 --> 00:00:03,000`. Переносы строк сохраняются. Разбиение сцен выполняется возле границ фраз примерно каждые 8 секунд; это временная разбивка, не анализ смысла. Длительность монтажа учитывает конец SRT и озвучки, загруженной до SRT. Для длинных роликов доступно до 600 сцен.

Если озвучка была добавлена после SRT и длиннее монтажа, импортируй SRT ещё раз или увеличь длительность сцен. При изменении/перестановке сцен абсолютные таймкоды субтитров остаются на месте. Если конец субтитров выходит за длительность монтажа, экспорт сообщит об ошибке вместо молчаливой потери текста.

## Что работает

- Пять оформлений по мотивам референса: тёплый кадр, монохром в зелёной рамке, крупная красная плашка, бумажная карточка цитаты и крупный тезис на тёмной сетке.
- Плавное приближение изображений; видео воспроизводятся с выбранного смещения. Если видео короче сцены, последний кадр удерживается до конца сцены.
- Растворение, сдвиг, вспышка, размытие, шторка, затемнение и прямая склейка. Выбор перехода для каждой сцены. Длительности округляются к сетке 30 кадров/с.
- Вшитые кириллические субтитры, озвучка и музыка с регулировкой громкости. Ограничитель пиков; плавное затухание музыки в конце фильма. Финальные слова озвучки не приглушаются.
- Экспорт H.264 в MP4, 16:9, 30 fps, 720p/1080p. При наличии звуковой дорожки — AAC.
- Автосохранение монтажа в браузере, сохранение/загрузка JSON, восстановление статуса экспорта после обновления страницы.

Заголовки могут плавно появляться и въезжать. Посимвольная анимация, выделение слов по голосу и сложные многослойные коллажи пока не реализованы. Предпросмотр сцены показывает статичную композицию; движение и итоговый звук проверяются в экспортированном MP4. Видеопревью «Архив» слегка отличается по тону от экспорта: экспорт использует нейтральный монохром.

## Данные и ограничения

- До 256 МБ на материал, до 1 МБ на SRT, 600 сцен, 60 минут на фильм; сцена — от 1 до 30 секунд.
- Один экспорт одновременно. Рендер выполняется на CPU; 1080p требует больше времени.
- Озвучка начинается в 0:00; короткое аудио дополняется тишиной, длинное обрезается длительностью монтажа с предупреждением в интерфейсе. Музыка не зацикливается. Звук исходных видео отключён.
- Субтитры и музыка не генерируются. Внешние AI API, ключи и аккаунты не нужны для текущего функционала.
- Материалы и экспорт находятся в `.data/`, не включаются в Git. Другое расположение задаётся `STUDIO_DATA_DIR`.
- JSON сохраняет параметры и идентификаторы материалов, **не сами файлы**. Для переноса между машинами нужно перенести также `.data/assets/`. Не удаляй эту папку, если материалы используются в проектах.
- После перезапуска сервера готовые экспорты сохраняются; прерванный рендер нужно запустить заново. Открытое браузерное окно/серверный процесс не переживают остановку облачной среды автоматически.

## Проверки

```bash
bash scripts/install.sh
.venv/bin/python -m unittest discover -s tests -v
```

Интеграционный тест загружает изображение, короткий видеоклип, озвучку, музыку и SRT; собирает MP4; проверяет длительность, количество кадров, декодирование, наличие видимых субтитров, слышимого сигнала и скачивание с Range-запросом. Звуковые сигналы в тестах синтетические, это не проверка качества речи.

Дополнительная проверка интерфейса: установи `requirements-ui.txt` и Chromium (`python3 -m playwright install chromium` или системный Chromium), затем запусти `python3 scripts/check_ui.py`. Можно задать `CHROMIUM_PATH`. Скрипт использует временные данные и отдельный сервер на порту 8001, проверяет загрузки, импорт SRT, редактирование, восстановление, экспорт и мобильную вёрстку. Скриншоты сохраняются в игнорируемый каталог `test-results/`.

Ручная проверка: загрузить собственные озвучку/SRT/изображения и оценить совпадение визуальных акцентов со смыслом текста. Подробный разбор присланного референса: [docs/reference-analysis.md](docs/reference-analysis.md).

## Импорт WebVTT

Поддерживаются файлы `.vtt` с заголовком WEBVTT, таймкоды с часами и без часов, идентификаторы фраз и многострочный текст. Блоки NOTE/STYLE/REGION пропускаются; оформление и позиционирование WebVTT заменяются стилем субтитров приложения. Таймкоды в проекте сохраняются до миллисекунды; в MP4 точность показа ограничена сеткой 30 fps и форматом ASS (сотые секунды).

## Переходы и звуковые акценты

В настройках фильма доступны растворение, плавный сдвиг, вспышка, размытие, шторка и чередование вариантов. Для каждой сцены можно отдельно выбрать переход к следующей. Короткие переходы занимают до 0,4 с, но не сокращают монтаж: таймкоды озвучки и субтитров остаются на месте.

Включи «Звуки переходов» для синтезированных взмахов, шелеста и акцента на вспышке. Эффекты создаются локально, без заимствования звука из референса; их громкость регулируется отдельно. Для прямой склейки эффект не добавляется. У изображений есть приближение, отдаление и панорамирование; анимация заголовков включается отдельно.


### Появление текста и звуковые акценты

В каждой сцене можно выбрать растворение, подъём снизу или въезд слева,
задать задержку от начала сцены и длительность появления. Время округляется
до ближайшего кадра (1/30 секунды). Фон и рамка остаются самостоятельными слоями.
Звуки «щелчок», «низкий удар» и «воздушный взмах» начинаются в момент появления
текста. Их громкость задаётся общим ползунком эффектов. Они работают независимо
от переключателя звуков переходов; «Без звука» отключает акцент конкретной сцены.
Статический предпросмотр показывает итоговый вид; движение и звук проверяются
в готовом MP4. Это оригинальные синтезированные эффекты, не звуки из референса.


## Версия 4: автоматические звуки и приёмы из нового примера

Новые проекты открываются с режимом «Автоматически · редко»: ориентир — 4 акцента
в минуту. Не нужно загружать или вручную назначать звуки. Программа выбирает
момент, характер звука и оставляет остальные переходы тихими. Общее число
ограничено длительностью ролика, акценты не накладываются друг на друга.
План с точными моментами показан в настройках. Короткий ролик может не получить
ни одного эффекта. Режим «Без эффектов» отключает их полностью; ручной режим
оставлен для старых проектов и индивидуальной настройки. Повторный экспорт
одного проекта сохраняет тот же план, без случайной смены звуков.

Ориентир 4/мин — предварительная оценка четырёх сильных стереотранзиентов
в файле 1017.mp4 длительностью 60,533 с. Это не подтверждённый слухом подсчёт:
тихие эффекты и музыка могут быть неотделимы от речи. Подробности — в
`docs/reference-profile.json` и `docs/reference-analysis.md`.

«Применить стиль примера» задаёт прямые склейки, прокрутку тезисов справа
налево, появление крупных акцентов и редкие звуки. Дополнительно доступны
подъём текста с перспективой, раскрытие строки, постепенная обводка и
подчёркивание. «Уводить текст влево» анимирует последние 0,35 с сцены.
Тайминги, длительность и выделение доступны для каждой сцены. Это
воспроизведение визуальных приёмов, не идентичный проект автора референса.
Статический предпросмотр показывает обычную композицию; анимацию и обводку
смотрите в экспортированном MP4.

## Поиск изображений

В блоке «Картинки из интернета» оставьте поисковую фразу пустой, чтобы запрос
строился из заголовка и пересекающихся по времени субтитров. Например,
«сохранилась только в Эфиопии» превращается в поиск эфиопской рукописи.
Можно ввести свою фразу на русском или английском. API-ключ не требуется.
На Wikimedia отправляется сформированная фраза, не аудио и не весь проект.

Поиск показывает результаты с источником и лицензией. Автоподбор заполняет
только пустые сцены, не заменяет ваши материалы и старается не повторять картинки.
«Остановить подбор» прекращает его после текущего запроса. Внимательно просмотрите
результат: ключевые слова и тематические правила не гарантируют историческую
достоверность и релевантность каждого изображения.

Картинки скачиваются в локальную библиотеку. Их автор, исходный URL и лицензия
сохраняются в метаданных. После экспорта доступна кнопка «Источники изображений»:
сохраните этот текст и выполните условия лицензий при публикации.

Для реального поиска нужен интернет к `commons.wikimedia.org` и
`upload.wikimedia.org`. В текущей облачной среде доступ заблокирован прокси
(403); домены добавлены в черновик настроек для сохранения пользователем.
Живой поиск в этой среде пока не подтверждён. Обработчики поиска, скачивания,
метаданных, интерфейс и ошибки проверены на контролируемых ответах сервиса.
На локальном компьютере используются обычные HTTPS-запросы к Wikimedia.


## Версия 5: футажи Pexels и Pixabay

1. В блоке **«Видеофутажи»** откройте **«Подключить Pexels / Pixabay»**.
2. Получите собственный API-ключ нужного сервиса на
   https://www.pexels.com/api/ или https://pixabay.com/api/docs/.
   Можно подключить только один сервис. Введите ключ в соответствующее поле
   программы и нажмите «Сохранить ключи». Не присылайте ключи в чат.
3. Выберите сцену и сервис. Оставьте поле «Что искать» пустым для запроса
   по заголовку и субтитрам сцены; при необходимости уточните поисковую фразу.
4. Нажмите «Найти футажи для сцены», просмотрите видео и нажмите
   «Скачать и вставить в сцену». Начало фрагмента меняется в поле
   «Начало видео, с». Если футаж короче сцены, последний кадр удерживается.

Подбор основан на тематических правилах и ключевых словах. Например,
«книга Еноха» даёт запрос `ancient book`, а «худшие годы жизни» —
`person hiking mountains`. Он не гарантирует точное соответствие каждого
результата содержанию рассказа: просмотрите найденные варианты.

Выбираются горизонтальные MP4: предпочтительно HD/Full HD, при отсутствии
таких вариантов — наименьшее доступное горизонтальное разрешение. Превью
использует уменьшенную версию, если она есть. Загрузка ограничена 256 МБ.
Звук футажа не включается в экспорт: используются ваша озвучка, подложка
и выбранные звуковые акценты. Автор, ссылка на оригинал и условия лицензии
сохраняются; список можно скачать после экспорта. Соблюдайте лицензии
Pexels/Pixabay и дополнительные ограничения на изображённых людей/бренды.

Ключи не передаются браузеру повторно и не входят в JSON проекта или ZIP
программы. При локальном вводе они хранятся на сервере приложения в
`.data/stock-keys.json` с правами 0600. Это локальный файл, не зашифрованное
хранилище; не публикуйте и не пересылайте каталог `.data`. Кнопка удаления
убирает локальный ключ выбранного сервиса. Также поддерживаются переменные
окружения `PEXELS_API_KEY` и `PIXABAY_API_KEY`, имеющие приоритет над локальным
вводом. В облаке задавайте их через защищённые поля настроек среды.

Программа использует официальные API. Ответы поиска кэшируются локально
на 24 часа; ключи в кэш не записываются. Пустая выдача, отсутствие ключа,
ошибка подключения и исчерпание квоты показываются пользователю.

Для облака необходим доступ к api.pexels.com, www.pexels.com,
videos.pexels.com, images.pexels.com, pixabay.com и cdn.pixabay.com.
Требования к доменам и двум ключам сохранены в черновике настроек среды.
На момент выпуска ключи не были предоставлены, а облачный прокси блокировал
внешние сервисы. Живой поиск с пользовательскими ключами не проверен.
Проверены оба адаптера на тестовых ответах, выбор MP4, приватность ключей,
кэш, импорт настоящего тестового видео, его вставка и экспорт, а также UI.


## Версия 5.1: подключение на Mac

HTTPS-запросы используют системные корневые сертификаты и пакет certifi.
Проверка сертификата и имени сервера остаётся обязательной. В блоке поиска
картинок есть «Проверить подключение»: она проверяет три сервиса, не передавая
ключи, и отдельно сообщает об ошибках SSL, DNS, прокси, таймауте и HTTP.
Успешная проверка соединения не подтверждает корректность API-ключа.

Если сайты открываются в браузере, а версия 5 не подключается, одна из
возможных причин на Mac — сертификаты Python. Для проверки этой причины
остановите программу Ctrl+C и из её папки выполните:

```bash
.venv/bin/python -m pip install certifi
SSL_CERT_FILE="$(.venv/bin/python -m certifi)" .venv/bin/python run.py
```

Это не отключает проверку HTTPS. Если причина другая, понадобится результат
диагностики. В версии 5.1 сертификаты подключаются автоматически; после
обновления зависимостей используется обычный запуск `python3 run.py`.
Не заменяйте старую папку целиком без сохранения `.data`: там материалы и
локальные настройки. JSON проекта хранится отдельно от самих медиафайлов.


## Версия 6: автоматическая расстановка фото и видео

Интерфейс стал тёмным: отдельные панели исходников, автомонтажа и оформления,
крупная зелёная кнопка подбора и фиолетовая кнопка экспорта. Ручной поиск фото
и видео свёрнут в раскрываемые панели слева. На карточках сцен видны тип
назначенного материала и отметка автоматического подбора.

**Чтобы собрать монтаж автоматически:**

1. Загрузите свою озвучку, затем SRT/VTT. Если включён «Запускать после
   загрузки субтитров», расстановка начнётся сама.
2. Для уже существующего проекта нажмите **«Подобрать и расставить»**.
3. Режим **«Фото + видео»** сам выбирает вид материала. Можно ограничить
   подбор только фото или только видео. Для поиска новых видео подключите
   хотя бы один API-ключ Pexels/Pixabay; локальные футажи доступны без ключа.
4. По умолчанию назначенные материалы сохраняются. Если хотите пересобрать
   уже заполненный монтаж, включите **«Заменять назначенные материалы»**.
5. Дождитесь завершения. В отчёте видны источник, тема и незаполненные сцены.
   Любую сцену можно открыть и изменить вручную. Затем экспортируйте MP4.

Сначала программа сопоставляет текст сцены и пересекающиеся с ней субтитры
с названиями и темами материалов библиотеки. Затем при необходимости ищет
материалы на внешних сервисах. Архивные темы, рукописи и документы предпочитают
фото; действие и пейзажи — видео. В смешанном режиме при отсутствии подходящего
варианта проверяется второй вид материала. Уже использованные ссылки
стараемся не повторять. Режимы «Только фото» и «Только видео» строго ограничивают
вид результата. Текстовые шаблоны «Цитата» и «Тезис» сохраняют собственный фон.

Это подбор по тематическому словарю, ключевым словам, описаниям и порядку
поисковой выдачи. Он не распознаёт содержание пикселей и не гарантирует
точного соответствия каждого кадра историческому факту. Файлы с непонятными
названиями без поисковых метаданных могут потребовать ручного назначения.
Посмотрите результат перед публикацией.

Прогресс сохраняется на сервере и в браузере; после обновления страницы
проверка продолжается. Уже назначенные кадры остаются при остановке.
Сетевой запрос или скачивание, которое уже идёт, завершается перед отменой.
Правки сцены, сделанные во время подбора, сохраняются вместо опоздавшего
автоматического результата. При недоступном источнике он не опрашивается
заново для каждой сцены; ошибка видна в отчёте. Незавершённый подбор после
перезапуска сервера отмечается как прерванный, можно запустить новый.

### Обновление установленного приложения на Mac

1. Сохраните проект кнопкой «↓ Проект» и остановите старую программу
   **Control+C** в её Терминале.
2. Распакуйте новый ZIP в отдельную папку.
3. В новой папке откройте **«Обновить Кадр.command»** и выберите **старую папку
   программы**, где лежат `run.py` и `.venv`. Помощник обновит код и зависимости
   и запустит программу в браузере.

Каталоги `.data` (материалы, ключи и задания) и `.venv` сохраняются. Предыдущие
файлы кода копируются в `.data/code-backups` перед заменой. Системное окно
выбора папки проверяется только на Mac; копирование и сохранность пользовательских
данных проверены автоматически. Если помощник запускается через Терминал,
используйте `python3 scripts/update_mac.py --target /путь/к/старой/папке`.

Проверены автоматическое назначение фото и настоящего видео, экспорт результата,
выбор по русским именам файлов и субтитрам, сохранение существующих материалов,
режимы, ошибки сервисов, восстановление после перезагрузки, отмена и защита
ручных правок. Проверки внешних API используют контролируемые ответы; условия
доступа и выдача сервисов на вашем компьютере могут отличаться.


## Версия 7: просмотр всего монтажа внутри приложения

После расстановки материалов нажмите **«▶ Смотреть монтаж»** над кадром.
При первом запуске программа подготовит облегчённый MP4 960×540. Прогресс
виден под плеером. Затем просмотр открывается на том же месте, где был
статический кадр. Первая подготовка занимает время, зависящее от длины ролика
и скорости компьютера; повторное воспроизведение готового просмотра идёт
без новой сборки.

В просмотр входят назначенные фото и футажи, их движение, озвучка, музыка,
автоматические звуковые акценты, субтитры, появления текста и переходы.
Используется тот же монтажный конвейер, что при экспорте, с облегчённым
разрешением 540p. Финальный экспорт остаётся в выбранном 720p/1080p.

- Кнопки и шкала самого видеоплеера позволяют запускать, ставить на паузу,
  перематывать, менять громкость и переходить в полноэкранный режим.
- **«С выбранной сцены»** начинает просмотр с начала выделенной сцены.
- Нажатие на карточку сцены во время просмотра ставит видео на паузу
  и переводит к началу этой сцены. Фиолетовая отметка в ленте показывает
  текущую воспроизводимую сцену.
- **«Изменить этот кадр»** возвращает к оформлению воспроизводимой сцены.
  Замените фото/видео или измените текст, затем нажмите **«Обновить просмотр»**.
- **«К редактированию»** возвращает статический кадр выбранной сцены.

После изменений приложение помечает старый просмотр и не запускает его как
актуальный. Если монтаж изменился во время подготовки, готовый старый снимок
также не воспроизводится автоматически. Ожидание подбора материалов отделено
от подготовки просмотра: сначала завершается автоматическая расстановка.

Готовый просмотр кэшируется. При перезагрузке страницы он восстанавливается
на паузе; если сборка ещё шла, продолжается проверка прогресса. Изменение имени
проекта или качества финального экспорта не требует повторной сборки просмотра.
Смена материалов, времён, текста, субтитров или звуков требует обновления.
На сервере сохраняются три последних готовых просмотра в `.data/playbacks`;
финальные экспорты не затрагиваются. Если кэш удалён, просмотр собирается снова.

Браузер может потребовать повторное нажатие ▶ после первой подготовки, чтобы
разрешить звук. Это отображается в подсказке плеера. Озвучка в библиотеке
останавливается при запуске монтажа, чтобы не звучали две дорожки одновременно.

Проверены настоящий MP4 540p, звук AAC, вшитые субтитры, точная длительность,
Range-запросы для перемотки, кэш, воспроизведение/пауза, выбор сцены,
возврат к редактированию, восстановление после перезагрузки и повторная
сборка после изменений. Интерфейс проверен в Chromium; формат видео
H.264/AAC предназначен и для Safari, но Safari в облачной среде недоступен.


## Версия 7.1: исправления сборки просмотра на Mac

В актуальных формулах Homebrew обычный `ffmpeg` не включает libass; полная
формула `ffmpeg-full` включает его. Прежняя инструкция `brew install ffmpeg`
не обеспечивала наличие фильтра `ass`, хотя программа использовала его для
вшивания субтитров. Исправлено: при отсутствии `ass` текст отрисовывается
встроенными шрифтами через Pillow и накладывается прозрачной дорожкой.
Озвучка, время показа субтитров и длительность ролика сохраняются. Ничего
дополнительно устанавливать для этого резервного пути не требуется.

Источники проверки состава формул:
https://github.com/Homebrew/homebrew-core/blob/master/Formula/f/ffmpeg.rb
и https://github.com/Homebrew/homebrew-core/blob/master/Formula/f/ffmpeg-full.rb.
Наличие проблемы на конкретном Mac подтверждается выводом FFmpeg или отчётом
сборки: одна общая ошибка просмотра сама по себе не устанавливает причину.

Ошибки просмотра теперь сохраняют этап сборки, ответ FFmpeg и сведения о его
возможностях. В приложении появляется **«Причина ошибки»**, кнопки
**«Скопировать отчёт»** и **«Скачать отчёт»**. Можно прислать этот текст вместо
длинного журнала проверок статуса. В отчёте скрываются домашние пути и URL.
В заданиях до 7.1 подробного отчёта нет — для его получения повторите просмотр
после обновления. Если диск недоступен, текст остаётся в интерфейсе.

Строки `GET /api/playback/... 200 OK` означают только успешное чтение статуса
задания, а не успешную сборку видео. Успех — состояние `done` и открывшийся
видеоплеер. Ошибка `address already in use` означает, что порт занят другим
запущенным экземпляром. Теперь запуск сначала резервирует порт, затем
открывает браузер. Если порт занят, появится понятное сообщение; новая вкладка
со старым сервером не открывается. Помощник обновления просит остановить старую
программу до замены файлов. Он не завершает посторонние процессы.

Резервные субтитры проверены реальным кодированием MP4 с отключённым в тесте
выбором libass: проверены текст, интервалы без текста, пересечения реплик,
число кадров и декодирование. Проверены отчёт об ошибке, скачивание из
интерфейса, приватность отчёта и обработка занятого порта. Сам Mac в облачной
среде недоступен; тесты воспроизводят соответствующие ограничения FFmpeg.


### Обновление v8: ритм, переходы и субтитры

В параметрах фильма нажмите **«Применить ритм и переходы»** для существующего проекта. Длинные сцены разделятся: первый кадр около 2–3 секунд, последующие около 4–5 секунд. Программа сохранит начало каждой старой сцены и подберёт материалы для новых сцен по тексту. Озвучка, длительность фильма и исходные таймкоды субтитров не сдвигаются. На длинных проектах ритм реже из-за ограничения в 40 сцен. Если все 40 сцен уже заняты, разделить их дальше нельзя.

Профиль чередует короткие растворения, шторки и размытие. Это приближение к монтажному языку примера, а не точная копия его авторских эффектов. Звуки остаются редкими: ориентир 4 акцента в минуту.

Снимите **«Показывать субтитры внизу»**, чтобы убрать нижний текст из просмотра и экспорта. Текст останется для поиска материалов. Отдельные заголовки сцен этим переключателем не скрываются.

Фотографии по умолчанию неподвижны. В **«Движение фотографий»** можно включить плавное движение с мягким разгоном и замедлением. После изменения настроек нажмите **«Смотреть монтаж» / «Обновить просмотр»**: ранее собранный MP4 сам не изменяется.


### v9: автоматическая режиссура

Требования пользователя сохранены в `docs/USER_REQUIREMENTS.md`. При загрузке
VTT/SRT программа сразу строит спокойные смысловые блоки (обычно 6–9 секунд,
вступление около 4–5), выбирает визуальные акценты и запускает поиск материалов.
Ручная настройка эффектов не нужна. Старый сохранённый проект получает этот
профиль один раз при первом открытии после обновления. Кнопка возврата
восстанавливает предыдущий монтаж; повторное открытие не переписывает правки.

Появления назначаются по тексту: тезис с жёлтой прокруткой на сетке;
упомянутый год крупными красными цифрами с обводкой; светлый текст
с перспективным появлением; документ в рамке над размытым фоном. Акценты
появляются в таймкод произнесённой фразы и затем скрываются, исходный кадр
продолжает держаться. Никакие даты, статистические данные или цитаты не
выдумываются. Картинки остаются неподвижными после короткого появления.

Это автоматический набор приёмов по референсу, не точное воспроизведение
всех его авторских эффектов. Понимание темы основано на субтитрах, названиях
и описаниях источников, без распознавания содержимого изображения. Теперь
результат без подтверждения темы в описании не назначается только за первое
место в выдаче. Конкретные страны/книги проверяются отдельно. Если подходящий
материал не найден, это показывается в отчёте; экспорт автоматического проекта
ожидает заполнения сцен вместо подстановки случайного демонстрационного фона.


### v9.1: сборка продолжается при отсутствии материалов

Автоподбор пробует альтернативный запрос, затем повторно использует уже
найденный материал с подтверждённой темой. Если подходящего фото/видео нет,
создаёт текстовую композицию из вашей озвучки. Она отмечается в отчёте;
случайные демонстрационные картинки не добавляются. Повторный автоподбор
может заменить такую композицию на подходящий материал.

Просмотр и экспорт больше не блокируются ошибкой «Ещё не подобраны
материалы». Старый проект с пустыми сценами автоматически дозаполняется
после обновления, без перестройки таймкодов и настроенных появлений.
Озвучка, длительность и переключатель нижних субтитров сохраняются.
FFmpeg без libass также поддерживается.


### v10: исправления по присланному film.mp4

При первом открытии старый проект с субтитрами автоматически получает
исправленный монтаж и заново проверяет материалы. Есть возврат к прежнему
проекту. Ручная настройка появлений не нужна.

Исправлены ложное распознавание «Рима» внутри «примерить», выбор архитектуры
вместо рукописи и потеря отрицания между cue. Короткие текстовые акценты
отделены от текста субтитров: несколько появлений могут идти внутри одного
кадра. Сетка остаётся неподвижной, движутся буквы; бумажная плашка показывает
мысль целиком; перспективный текст не переносится в начало сцены.
Рамка сохраняет пропорции исходной страницы. Общая видеодорожка получает
единые параметры кодирования и регулярные ключевые кадры.

При отсутствии подтверждённого изображения используются бумажные карточки
с исходным текстом, без случайных картинок или имитации исторического
документа. Подбор по-прежнему основан на описаниях материалов. Положения
слов внутри cue оцениваются по тексту: это не точное выравнивание по фонемам.
Подробный разбор и ограничения: `docs/review-film-v10.md`.

Упомянутое в речи количество людей/участников может автоматически
появляться как счётчик с синей круговой обводкой. Количество берётся только
из субтитров: чужая статистика из примера в ваш фильм не переносится.

### v11: появления по новому примеру 1018.mp4

Автоматические цифры со свечением, рисующейся петлёй и бегущим бликом;
белая курсивная дата с цветной тенью; курсивная датировка поверх тёмного кадра;
боковая панель с документом во вступлении. Даты берутся только из субтитров.
Фото после появления не двигаются. Звуки теперь стерео, редкие и привязаны
к пику движения. Один акцент на границе сцен звучит один раз.

Закройте старый сервер Ctrl+C и запустите «Обновить Кадр.command» из нового
архива, выбрав прежнюю папку приложения. Проект получит профиль v11 один раз;
копия прежнего монтажа доступна через возврат. Медиа и ключи сохраняются.
Разбор и ограничения: `docs/reference-1018.md`.

### v12: исправление неполного видеоряда и неподходящих стоков

Проверка и восстановление временных меток до преобразования частоты кадров;
контроль числа кадров, времени и частоты каждой сцены и готового MP4.
Неполный экспорт больше не получает статус «Готово». Старый кэш просмотра
не используется новым рендером. Сохранены голос, длительности и тайминг cue.

В истории книги Еноха абстрактное испытание и писание сохраняют связь с книгой;
офисные сцены, ноутбуки и современные тетради не проходят автоматический
фильтр исторических материалов. Старые автоматические назначения также
проверяются; ручные сохраняются. Фразы «НЕ НАКАЗАНИЕ» и «СТИХ ЗА СТИХОМ»
получают появления в стиле референса. Подробно: `docs/review-user-film-v12.md`.

### v12.1: субтитры длиннее 10 минут

Исправлен отказ на таймкоде 601,334 с. SRT/VTT и проект теперь поддерживают
до 60 минут, 600 сцен и 10 000 cue без сдвига и обрезки таймкодов. Для более
длинного файла импорт показывает понятное сообщение по-русски. Проверены
импорт точного проблемного таймкода, сохранение/открытие JSON и планирование
полного часа. Часовой экспорт целиком не использовался как тест.

Звуковые эффекты записываются в разреженный WAV по коротким фрагментам;
час тишины больше не требует гигабайтного массива в оперативной памяти.
Старые проекты не получают повторную перестройку при установке v12.1.
Обновление: закройте сервер Control+C, распакуйте новый архив и запустите
«Обновить Кадр.command», выбрав прежнюю папку приложения.
